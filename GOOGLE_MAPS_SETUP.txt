BAKE & GRILL — GOOGLE MAPS BROWSER KEY SECURITY
Updated: 19 November 2026

CURRENT APP.JS USAGE
The production customer site loads the Google Maps JavaScript API and uses:
- Maps JavaScript API (map rendering and library loader)
- Routes library / Route.computeRoutes for driving road-distance calculations (Routes API)
- Geocoder for address lookup and reverse geocoding (Geocoding API)
There are no current google.maps.places references in app.js. Do not enable or allowlist Places API unless it is reintroduced in the code.

PRODUCTION HOST
Primary website: https://bakeandgrill.in
Allowed referrer pattern for the Maps browser key:
- https://bakeandgrill.in/*
Only add https://www.bakeandgrill.in/* if www actually serves the website.
Only add https://bgpizza.github.io/online/* if that alternate host is intentionally used to run customer or Master pages. Remove temporary/local/development hosts from the production key.

CREATE A NEW MAPS KEY
The existing Maps browser key was exposed in a public client file and previously shared in chat. Treat it as exposed and rotate it:
1. Google Cloud Console → APIs & Services → Credentials → Create credentials → API key.
2. Name: BakeGrill Maps Production.
3. Application restrictions: Websites (HTTP referrers).
4. Add only the production referrer patterns above.
5. API restrictions: Restrict key; allow only:
   - Maps JavaScript API
   - Routes API
   - Geocoding API
6. Save. Test map rendering, address lookup/reverse geocoding, road distance, manual pin drag and order checkout on bakeandgrill.in.
7. After confirming the new key works, replace GOOGLE_MAPS_API_KEY in app.js with the new key, deploy, verify again, and delete/disable the old key.

IMPORTANT
- The Maps key is a browser key and will be visible in page source. That is expected; security comes from HTTP-referrer restrictions, API restrictions, quotas and billing alerts.
- Never use this browser key for server-side web-service calls.
- Do not put the Maps key into firebase-config.js or reuse the Firebase Web API key for Maps.
- Do not add Places API without a feature in the deployed code that uses it.
- Avoid restrictive quotas that unintentionally stop customer address resolution or delivery-distance calculation; set reasonable daily quotas and billing alerts after observing normal usage.
